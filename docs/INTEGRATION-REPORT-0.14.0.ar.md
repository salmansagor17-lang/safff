## ما تغيّر وما أصلحناه

قاعدة البيانات أصبحت تستخدم 100 و300 و500 نقطة، بينما الواجهة كانت تشترط وجود أسئلة بدرجات 200 و400 أيضًا. لذلك كانت دالة صلاحية التصنيف تستبعد التصنيفات الحالية من اللعب. أصبحت اللعبة تستخدم الدرجات الثلاث، بسؤالين لكل درجة: 6 أسئلة لكل تصنيف و12–30 سؤالًا للجلسة، بما يطابق إعدادات اللعبة في Supabase.

| البيان | قبل المزامنة محليًا | المصدر الحالي |
|---|---:|---:|
| الأسئلة | 3022 | 3286 |
| التصنيفات النشطة | 20 | 20 |
| أسئلة الصور | 550 | 1050 |
| الميكاب | 300 سؤال نصي | 500 سؤال مصور |
| Prison Break | غير موجود | 300 سؤال |

تصنيف `fc-quran` السابق غير موجود في المصدر الحالي. تم احترام هذا التغيير؛ لم نعد إنشاء محتوى محذوف ولم نكتب فوق قاعدة البيانات. ما زالت تصنيفات قصص القرآن والسيرة والمعارف الإسلامية موجودة.

أضفنا قراءة `image_path` و`image_alt` للتصنيفات، وعرض غلاف Prison Break من Storage. جرى تحديث البنك الكامل والبنك المصغر وإحصائيات المحتوى وشرح الصعوبة وعدد أسئلة الجلسة. يتضمن البنك المصغر 120 سؤالًا تغطي جميع التصنيفات والدرجات الثلاث.

## التحقق

- نجحت الاختبارات الآلية الـ21، بما فيها إكمال اللعب وإعادة البدء في أوضاع المصدر المباشر والبنك المحلي والبنك المصغر، باستخدام محاكاة DOM.
- تطابقت 11 صفحة وملف تشغيل منشورة مع ملفات مساحة العمل، بما فيها `shared/palette.css`.
- نجح `verify-production.cjs` على الموقع العام: تطابقت الأسئلة الـ3286 ومحتواها ونقاطها وخياراتها وبيانات الوسائط مع النسخة المحلية، وكانت التصنيفات العشرون قابلة للعب.
- استجابت جميع روابط صور الأسئلة الـ1050 بحالة 200 ونوع محتوى صورة، وكذلك أغلفة التصنيفات والشعار. تم التحقق من تكوين جلسة بخمسة تصنيفات و30 سؤالًا، سؤالين لكل درجة.
- تطابق البنك الاحتياطي المنشور مع المحلي بالكامل، وأعادت مسارات ملفات الإدارة والنسخ الاحتياطية المختبرة 404.
- أكد GitHub نجاح فحص Vercel، وأكدت واجهة Vercel أن النشر ناتج عن commit المذكور.
- فحصا الأمان والأداء في Supabase لم يعيدا أي تنبيهات. RLS مفعّل على الجداول العامة الأربعة.
- تمت مراجعة سياسات القراءة العامة للمحتوى، وسياسة إدخال التقييمات وحدودها. لم تُرسل تقييمات تجريبية ولم تُقرأ تعليقات المستخدمين.
- أعاد طلب قراءة معرفات التقييمات بالمفتاح العام HTTP 401؛ لم يكشف أي سجل.
- لم تُرجع سجلات Vercel أخطاء للنشر عند فحص الساعة الأخيرة؛ التطبيق ثابت ولا يملك خادم تطبيق خاصًا.
- الفحص البصري في المتصفح غير متاح في هذه الجلسة؛ لا تدّعي الاختبارات البرمجية التحقق من الشكل على الهاتف أو التلفزيون.

## الربط والإعداد

Vercel مربوط بمستودع `salmansagor17-lang/safff` وفرع الإنتاج `main`. التطبيق HTML/CSS/JavaScript ثابت ويقرأ عنوان Supabase ومفتاحه العام من `js/config.js`؛ عدم وجود متغيرات بيئة في Vercel لا يمنع هذا الربط. لم تُنشر مفاتيح إدارة أو ملفات البيئة.

موصل Vercel داخل الجلسة أعاد 403، لكن جلسة CLI المصرح بها نجحت في الوصول إلى المشروع وفحص الربط والنشر. لا يدل خطأ الموصل على تعطل الموقع.

## المزامنة القادمة

```powershell
node --use-system-ca scripts/sync-content.cjs
node --test scripts/test-content-store.cjs scripts/test-session-questions.cjs scripts/test-game-flow.cjs scripts/test-setup-flow.cjs scripts/test-topic-expansion.cjs
```

راجع التغييرات، ثم ارفعها إلى GitHub وانتظر اكتمال النشر، وبعدها:

```powershell
node --use-system-ca scripts/verify-production.cjs
```

سكربت المزامنة يقرأ Supabase بالمفتاح العام فقط، ويتحقق من اكتمال الصفحات وتفرّد المعرفات وكفاية الدرجات، ويحفظ النسخة السابقة في `.local-backups/content-sync-*`. لا توجد مزامنة تلقائية مستمرة من Supabase إلى Git؛ يلزم تشغيله بعد تغييرات المحتوى. ملفات الإدارة والتقارير والنسخ المحلية مستبعدة من النشر.

تظل صور Storage بحاجة إلى اتصال حتى عند استخدام نسخة الأسئلة المحلية. ملف `scripts/fetch-makeup-images.py` غير المتتبع كان موجودًا قبل هذه المهمة وتُرك كما هو خارج commit التحديث.
